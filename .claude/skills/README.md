# 两个产品 Skill

给 Claude Code 用的两个小工具。装上之后，你正常说话就会被自动调起，**不需要记任何命令**。

| Skill | 帮你解决什么 | 什么时候用 |
|---|---|---|
| **`prd-coach`** | 把「我想做个 X」追问成一份能直接开工的需求文档 | 有想法，但还没想清楚 |
| **`biz-review`** | 判断这件事作为生意到底成不成立 | 东西做出来了，在想能不能卖 |

两个 skill 对应两条不同的路：**只是自己用**，`prd-coach` 就够了；**想做成生意**，才需要 `biz-review`。

---

## 安装

### 方式一：全局安装（推荐，所有项目都能用）

```bash
git clone https://github.com/rance811-maker/product-skills.git
mkdir -p ~/.claude/skills
cp -r product-skills/prd-coach product-skills/biz-review ~/.claude/skills/
```

### 方式二：只装到某一个项目里

把 `prd-coach/` 和 `biz-review/` 两个文件夹，复制到你项目根目录的 `.claude/skills/` 下：

```
你的项目/
└── .claude/
    └── skills/
        ├── prd-coach/
        │   └── SKILL.md
        └── biz-review/
            └── SKILL.md
```

装好后，在 Claude Code 里输入 `/skills`，能看到它们就说明成功了。

## 怎么用

**不用记命令，正常说话就行：**

```
我想做一个帮我孩子练英语语法的小工具
```
→ 自动进入 `prd-coach`，开始一条条追问，最后给你一份 `PRD.md`

```
我这个东西能不能商业化？
```
→ 自动进入 `biz-review`，五个维度逐条评审，最后给结论和评分

也可以直接点名叫它：

```
/prd-coach
/biz-review
```

## 它们分别会问你什么

### `prd-coach`：四组问题

| 组 | 问什么 |
|---|---|
| **要什么** | 谁在什么场景用？现在怎么凑合的？那个「痛」是什么？做完之后什么变了？ |
| **拿什么做** | 需要哪些数据/内容？**它们现在在哪，你拿得到吗？** 用户填、你预备，还是接进来？ |
| **不要什么** | 这一版明确不做什么（至少 3 条）？有什么绝对不能碰？ |
| **怎么算对** | 什么样算做对了？**什么样看着像做完了，其实是错的？** |

后三组是新手几乎必漏的，其中两组最致命：

- **「拿什么做」**——很多想法不是需求不清楚，是**依赖的东西根本拿不到**。AI 让实现变便宜了，瓶颈就前移到"你手上有没有原料"，模型再强也变不出你没有的数据。
- **「怎么算对」**里的那个**反例**——它能把你脑子里那些"不言自明"的标准逼出来，省掉后面一半返工；同时它也是迭代的地基：没定义什么算对，就无从判断一次改动是变好还是变坏。

### `biz-review`：五个维度，每个都有红线

| 维度 | 🚩 红线 |
|---|---|
| 价值验证 | 只有「有人说好」，没有任何付费意愿的证据 |
| 成本结构 | 每多一个用户成本就线性增长，且无法摊销（另外还会问：它**会不会越用越好**？） |
| 交付与账号 | 核心能力依赖用户自己配环境、自己填 key |
| 信任与合规 | 高后果领域（教育/医疗/钱），却没有独立于 AI 的验证机制 |
| 增长 | 说不出第一批 100 个用户具体从哪来 |

**红线优先于总分**：任何一个维度触红线，直接判「当前不成立」，不许用其他维度的高分平均掉。

## 两句话心法

> **AI 不会拒绝一个烂需求。它会非常认真、非常快地，把你的烂需求实现出来。**
> 所以动手前，先用 `prd-coach` 把需求逼清楚。

> **代码是最便宜的部分。商业化要解决的，全是代码解决不了的。**
> 所以投入前，先用 `biz-review` 照照镜子。
