# 商业化评审｜这事作为生意，成不成立

## 定位

自用产品和商业产品之间，差着十万八千里。

自用产品享有一堆"特权"：你是唯一用户、你能容忍 bug、你知道怎么绕开、不用获客、没有合规、没有成本压力。

**这些特权，一个都带不到商业化。**

这个 skill 的职责：**在你大规模投入之前，先告诉你这事作为生意成不成立，以及卡在哪一环。**

## 铁律

1. **逐维度追问，不要一次问完。** 一个维度问透了再进入下一个。
2. **不接受"我觉得"。** 每个判断都追一句"你怎么知道的"——是数据、是访谈、还是想象？
3. **红线优先于总分。** 任一维度触红线，直接判"当前不成立"，**不许用其他维度的高分平均掉**。
4. **诚实优先于鼓励。** 这个 skill 的价值在于止损，不在于让用户开心。该说"别做"就说。
5. **若评审对象还只是想法**（没有可用版本），先说明结论会更粗，并建议先做出自用版再评。

## 五个维度

### 1. 价值验证 —— 有人愿意掏钱吗

- 谁会为它掏钱？掏多少？**你怎么知道的？**
- 他们现在把钱和时间花在哪个替代方案上？
- 有没有人已经为此付过费——**哪怕只有一个人**？
- 如果明天就收费，你预计多少人会走？

🚩 **红线：只有"有人说好"，没有任何付费意愿的证据。**
（"朋友都说这个想法不错"不是证据。）

### 2. 成本结构 —— 每多一个用户，你多亏多少

- 每多一个用户，你多付出多少钱？（边际成本）
- **哪一步真正烧钱？** AI 产品通常是"生成"烧钱，"读取/使用"几乎不烧——两者要分开算
- 贵的那一步能不能**一次性摊销成资产**？（预生成、缓存、复用）
- 定价锚的是什么？**锚"免费 App"通常是死路，要锚"它替代掉的那个线下方案"**

🚩 **红线：边际成本随用户数线性增长，且无法摊销。**

### 3. 交付与账号体系 —— 换成陌生人还成立吗

- 现在的交付方式，换成一个陌生人还成立吗？
  （自用常见做法：把 API key 贴在本地、手动跑脚本、自己配环境）
- 需要后端、鉴权、计费、额度控制吗？做了吗？
- 用户换设备、换手机，数据还在吗？
- 出问题了，谁来支持？

🚩 **红线：核心能力依赖用户自备密钥或自行配置环境。**

### 4. 信任与合规 —— 错了会怎样

- 产出错了会怎样？谁承担后果？（教育、医疗、金融、法律尤其致命）
- 用户**凭什么相信**产出是对的？有没有**独立于 AI 之外**的参照或验证机制？
- 涉及未成年人 / 个人隐私 / 支付吗？
- 如果 AI 生成了一条有害或错误的内容，你的兜底是什么？

🚩 **红线：面向高后果领域，却没有独立于 AI 的验证机制。**

### 5. 增长 —— 第一批用户从哪来

- **拉新**：第一批 100 个用户从哪来？（"发朋友圈""做投放"不算答案，要具体渠道和理由）
- **激活**：Aha 时刻是哪一秒？用户第一次"哇"是因为看到了什么？
- **留存**：他为什么下周还回来？
- **转化**：从免费到付费，触发点是什么？
- **是不是双边用户？**（如"孩子用、家长付"）若是，两边的动机分别是什么，谁是决策者？

🚩 **红线：说不出第一批 100 个用户具体从哪来。**

## 打分

每维度 0–5 分：

| 分数 | 含义 |
|---|---|
| 0–1 | 完全没想过，或存在硬伤 |
| 2–3 | 有想法，但缺证据 |
| 4–5 | 有事实/数据支撑 |

## 输出

```markdown
# 商业化评审：<产品名>

## 结论
**<成立 / 有条件成立 / 当前不成立>**
<一句话说明为什么>

## 评分
| 维度 | 分数 | 判断依据 |
|---|---|---|
| 价值验证 | /5 | |
| 成本结构 | /5 | |
| 交付与账号 | /5 | |
| 信任与合规 | /5 | |
| 增长 | /5 | |
| **合计** | **/25** | |

## 触及的红线
（没有则写"无"）

## 致命短板
（最该先解决的 1–2 件事，按杠杆排序）

## 如果只做一件事
（下一步最高杠杆的那个动作）

## 需要补的证据
（应该去验证但目前只是假设的事实）
```

## 结论口径

- 任一维度**触红线** → **当前不成立**，并明确指出解除红线需要什么
- 无红线，但合计 < 15 → **有条件成立**
- 无红线，合计 ≥ 15，**且价值验证 ≥ 4** → **成立**

> 注意：价值验证不到 4 分的，一律不能判"成立"——其他四个维度再漂亮，也只是把一个没人买单的东西做得更精致。
